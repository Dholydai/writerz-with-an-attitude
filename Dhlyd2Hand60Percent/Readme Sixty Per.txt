3D-print settings:

The minimalist case requires manually 'enforcing' supports inside of the USB port.
Full auto support generation is not suggested. The support that is created inside
of the left section's screw hole is difficult to remove (PETG makes supports stick).  

KMK code:

Separate codes for left and right 60% keyboards would required swapping of
the 'Fn' and 'Menu' keys.

So, it seemed better to make a keyboard with a left and a right 'Fn' key. Left
key activates a right-hand layer, the right key activates a left-hand layer.

The ambidextrous code is well-behaved. Good code.

However, it is confusing: What 'Fn' key was pressed? What layer is active?

The PCB design includes provision for LED indicators under the 'Fn' keys.

The KMK code to support those discrete LED layer indicators does not exist.
Creating that two-LED layer indicator code requires the KMK project's collaboration.
